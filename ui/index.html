What this app does — and does not

Stackdeck starts, supervises and stops the local services your projects need, and provisions them with generated credentials. Servers run loopback-only and die with the app: closing it stops everything instead of leaving an orphaned database behind.

Sites are still hand-written into Caddyfile — there is no add-site form yet, so a new project needs a vhost block added there. Everything else is wired: PHP executes and dotfiles are denied.

1. First run
  1. Open the Setup panel. Each service shows not installed.
  2. Press Install. Homebrew installs it; the row updates on its own.
  3. Press Set up. Credentials are generated — you never type one.
  4. Every row reads ready when the machine is prepared.

Installs need Homebrew and an internet connection. Set up is idempotent; running it again keeps the existing password.

2. Starting and stopping services
  1. Pick a Preset — it fills Name, Program and Args.
  2. Press Start.
  3. The service appears under Running with its pid. Press Stop to end it, or stop the whole tree by quitting the app.

Start MariaDB before anything that needs a database. PHP alone serves nothing.

Start order that works: MariaDB → PHP → phpMyAdmin. Each server needs a few seconds before it accepts connections.

3. Addresses and ports
ServiceAddressBound to
MariaDB127.0.0.1:3306, socket /tmp/stackdeck.sockall interfaces
Caddy (sites)http://<site>.localhost:8080loopback only
phpMyAdminhttp://127.0.0.1:8081loopback only
PHP-FPMunix socket, no TCP portsockets

MariaDB listens on all interfaces because the LAN/devices need it — it is password-protected. phpMyAdmin and FPM never leave the machine.

4. Credentials

The MariaDB root password is generated at setup and stored in your Keychain as service stackdeck-mariadb.

security find-generic-password -s stackdeck-mariadb -w

User is root. phpMyAdmin's own secret lives in its config and needs no attention.

App .env files still need this password. Imported projects ship with an empty DB_PASSWORD.

5. Choosing a PHP version

Versions are installed side by side; each has its own socket, so they do not collide.

PresetUse for
PHP 8.5new work — breaks Laravel 10 and older
PHP 8.3Laravel 10 / 11
PHP 8.1Laravel 8 / 9 legacy

If a project 500s with a parse error, it is almost always the wrong PHP version.

6. Where files live 
~/Library/Application Support/Stackdeck/
  data/          MariaDB datadir
  phpmyadmin/    symlinks + generated config
  run/           PHP-FPM sockets and pid files
  log/           service logs
  tmp/           phpMyAdmin scratch

Service output goes to log/<service>.out.log and .err.log. Read those first when a service will not stay up.

7. Troubleshooting
“Address already in use”
Something else holds the port — often XAMPP. Check with lsof -nP -iTCP:3306 -sTCP:LISTEN.
Service starts then disappears
Read log/<service>.err.log. A datadir permission problem or a missing package shows there.
Row stuck on “not installed”
Homebrew failed. Run brew install <formula> in a terminal to see the real error.
phpMyAdmin cannot log in
Confirm MariaDB is running first, and copy the password from Keychain exactly.
“command not found” for mysql
Use the full path /opt/homebrew/opt/mariadb/bin/mariadb; XAMPP still shadows the short name.
8. Known limitations
  • No Caddy, no per-site vhosts — see 1.
  • phpMyAdmin runs on PHP's built-in server: single-threaded, HTTP only.
  • macOS only. The Windows manifest exists but nothing reads it.
  • Presets contain absolute paths, so this only runs from a source checkout.
  • No import wizard; `.env` rewriting is manual.
